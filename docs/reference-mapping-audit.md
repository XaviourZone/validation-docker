# Reference Mapping Audit\n\n## Purpose\n\nThe Validation parser has 41 canonical XTrack fields. This audit prevents the mapping from being based only on the fields already exposed by ReferenceDB.\n\nThe authoritative relationship is:\n\n- WRS: resolve a vessel and use VESSEL_ID as the common relationship key across WRS datasets.\n- PANS: use the consolidated PANS vessel/voyage data produced from VESPRO, CALINF, CALINV and BERMAN.\n- NSC: use identity/classification/security-reference fields; NSC is not treated as a voyage source.\n- AIS: remains authoritative for dynamic transmission values such as position, speed, course, heading, message ID and transmitted MMSI.\n\n## Audit command\n\n    python3 scripts/reference_mapping_audit.py --wrs-db Validation/Database/WRS/wrs.db --pans-db Validation/Database/PANS/pans.db --nsc-db Validation/Database/NSC/nsc.db --output runtime/reference-mapping-audit\n\nOutputs:\n- reference_mapping_audit.json — complete table/column inventory and 41-field candidates.\n- reference_mapping_audit.csv — compact field-to-source candidate matrix.\n\n## Rules\n\n1. A reference field is used only when its semantics match the XTrack field.\n2. Incoming AIS remains authoritative for live/dynamic values.\n3. id.mmsi and sys.track.number remain the transmitted identifier.\n4. WRS VESSEL_ID is used to relate all WRS datasets after vessel resolution.\n5. PANS voyage fields are selected by document semantics: CALINF for origin/ETA/ETD and voyage registration; BERMAN for destination/berth/cargo/operational voyage information; VESPRO for static vessel particulars; CALINV for VCN/voyage identifiers.\n6. NSC does not supply voyage values because its current schema contains no voyage attributes.\n7. Do not derive bow/stern/port/starboard dimensions from LOA or beam.\n8. Do not put a port name into a date field.\n9. Do not fabricate a value merely to increase XML field coverage.\n10. Every fallback must remain traceable to its source.\n\n## Production interpretation\n\nA field can be Incoming-only, Reference-enrichable, Derived, or Unresolved.\n\nThe audit is intentionally non-destructive. It does not modify WRS, PANS, NSC or parser configuration.
